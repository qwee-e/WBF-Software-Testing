# 成员一（lry）模块1人工测试

分工按用户截图：01、03、05、07、09、11、13、15、17、19、21、23、25、26、29，共 15 条；包含 26，不包含 27。用例来自用户提供的 Excel 清单，输入原文保存在 `test_data/member_a/source_inputs.json`，原始附件副本保存在同目录。

这些是依据指定清单人工确定预期值、再由 pytest 自动执行的模块测试，与 `tests/` 的官方自带测试和先前的基线复现区分。工具协助编写和执行，需成员一复核，不能描述成未经工具辅助的独立人工执行。

## 执行方式

在项目根目录，使用成功复现的 `.venv`：

```powershell
.\.venv\Scripts\python.exe -m pytest manual_tests/member_a -v
```

指定用例可使用 `test_wbf_member_a.py::test_001__single_valid_box` 这样的节点。增加 `--member-a-report=输出路径.json` 可以记录原始输出、数组形状、警告、异常、时间、环境及被测源码哈希。

## 预期与状态

- 正常用例使用执行前写入 JSON 的手算预期，断言坐标、分数、类别、形状和警告；浮点比较 `rtol=1e-6, atol=1e-7`。
- `OK` 表示符合已声明预期，`NG` 表示断言失败，未执行项不填成通过。不用 xfail 把缺陷断言变成通过。
- 23、25 的预期为显式 `ValueError`，这是建议的健壮性契约，不是上游已经保证的异常类型。失败表明该建议契约未满足，需区分“行为已复现”与“缺陷定性待评审”。
- 26 检查零分框不能造成 NaN/Inf；允许明确拒绝或返回有限合法结果，不强行规定零分框的唯一业务处置。
- 07 保留表格输入，并补充精确等值及相邻浮点阈值验证，避免将舍入输入误称为精确等值覆盖。

每完成两条用例就保存执行记录、回填成员一的表格副本并提交上传，最后剩余的 29 单独上传。每批次日志和 JSON 保存在 `results/`。结果报告及 Excel 位于 `docs/member_a/`，缺陷材料位于 `defects/member_a/`。不修改被测算法，不移动冻结标签，也不填写成员二的测试结果。
